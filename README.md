این مخزن مرجع رسمی و ماشین‌خوان وب‌سرویس پنل پیامکی پیام رسان است و توسط تیم
محصول و توسعه ما نگهداری می‌شود. قراردادهای این مخزن مبنای تولید مستندات،
نمونه‌کدها، کلاینت‌ها و ابزارهای ما از جمله سرور MCP هستند.
مسئولیت ما ثبت دقیق قرارداد و رفع اختلاف آن با پیاده‌سازی سرویس است.

## چیدمان

```text
specs/
├── v3/
│   ├── openapi.yaml
│   └── codes/
└── v4/
    ├── openapi.yaml
    └── codes/
scripts/
└── validate.py
```

توصیف [نسخه ۳](specs/v3/openapi.yaml) شامل ۱۳ عملیات در ۱۱ مسیر است.
توصیف [نسخه ۴](specs/v4/openapi.yaml) شامل ۲۶ عملیات در ۲۴ مسیر است.
هر نسخه پوشه مستقل دارد؛ افزودن نسخه تازه موجب جابه‌جایی یا تغییر نام فایل‌های نسخه‌های موجود نمی‌شود.

توصیف‌های OpenAPI و جدول‌های کد مستقیماً در پوشه `specs/` نگهداری می‌شوند.
تغییر هر نسخه باید اطلاعات تأییدشده آن نسخه را حفظ کند.

## مبنای صحت قرارداد

مرجع نسخه ۳ شامل اطلاعات تأییدشده مستقیم تیم توسعه و افزوده‌های Swagger است.
توضیح‌ها، خطاها، سیاست‌های تلاش دوباره و استعلام وضعیت از
مرجع [نسخه ۳](specs/v3/openapi.yaml) حفظ می‌شوند.
نسخه ۴ با ساختار همین مرجع و اطلاعات مستقل همان نسخه نگهداری می‌شود.

نشانی‌های آزمایشی تأییدشده ما:

- نشانی نسخه آزمایشی ۳: `https://www.payam-resan.com/api/V3SandBox`
- نشانی نسخه آزمایشی ۴: `https://www.payam-resan.com/uapi/v4SandBox`

متد `SendMultiple` نسخه ۴ طبق قرارداد منتشرشده در محیط آزمایشی ارائه نمی‌شود.

## قرارداد نسخه ۴

سرویس نسخه ۴ ارسال تکی و گروهی، ارسال قالبی، رمز یک‌بارمصرف پیامکی و صوتی،
استعلام وضعیت و اعتبار، صندوق ورودی، دفترچه تلفن و مدیریت کمپین را پوشش می‌دهد.
بیشتر عملیات‌ها `POST` هستند؛ دو عملیات ارسال قالب، مسیر `GET` نیز دارند.
کلید در بدنه JSON یا پارامتر query قرار می‌گیرد؛ هدر اختیاری `source-app` برای ثبت نام برنامه است.

متد `POST /uapi/v4/GetToken` با بدنه `{"apiKey":"YOUR_API_KEY"}`
فهرست قالب‌ها و وضعیت تأیید آن‌ها را برمی‌گرداند؛ توکن ورود تولید نمی‌کند.
کلید این درخواست رشته غیرقابل `null` است. پاسخ شامل فیلد `success` است؛
فیلدهای دیگر آن `errorCode`، `error`، `moreInfo` و `result` هستند.
هر قالب دارای `key`، `textTemplate` و `status` است؛ فیلد قالب صوتی در این پاسخ وجود ندارد.

زمان‌های نسخه ۴ بدون پسوند منطقه زمانی و بر مبنای وقت محلی تهران،
با مبنای `UTC+03:30`، هستند. فیلدهای `date-time-local` قالب
زمان `YYYY-MM-DDTHH:mm:ss` با بخش اعشاری اختیاری ثانیه دارند؛ پسوند
منطقه زمانی به آن‌ها اضافه نمی‌شود. نمونه‌های کمپین همین قالب را دارند.

سیاست‌های نسخه ۳ پس از تطبیق قابلیت و معنای کد به‌عنوان مرجع نسخه ۴
به کار می‌روند: سیاست تکرار برای ۱۹ خطای هم‌معنا، دسته‌بندی هر ۲۲ وضعیت
تحویل، استعلام دسته‌ای با فاصله چند دقیقه و امکان ارسال فقط برای قالب تأییدشده.
وضعیت رد قطعی قالب در نسخه ۴ کد مستقل `4` دارد.
کد خطای `20` در نسخه ۴ سهمیه OTP است؛ محدودیت نرخ HTTP با `429`
مشخص می‌شود. جدول‌های نسخه ۴ مرجع هر سیاست را ثبت می‌کنند.

## آنچه باید درباره پاسخ‌های V3 بدانید

سه رفتار V3 سرویس که در هر ادغامی تعیین‌کننده‌اند:

<div dir="rtl">

| رفتار                                  | یعنی چه                                                     |
| -------------------------------------- | ----------------------------------------------------------- |
| همه پاسخ‌ها `200` هستند                | موفقیت از فیلد `Success` خوانده می‌شود، نه از کد وضعیت HTTP |
| فیلد `ErrorCode` فقط در شکست معنا دارد | تا `Success` برابر `false` نباشد، خواندنش بی‌معناست         |
| کلید در خود درخواست است                | در `GET` پارامتر query و در `POST` یک فیلد بدنه، نه یک هدر  |

</div>

جزئیات کامل هر سه رفتار V3 در بخش `info` از
توصیف [`openapi.yaml`](specs/v3/openapi.yaml) آمده است.

## چرا جدول‌های کد V3 جدا از spec

مقادیر `ErrorCode` و `StatusCode` در V3 در دو جا لازم‌اند: به‌عنوان `enum` در
اسکیمای پاسخ، و به‌عنوان جدولِ «این عدد یعنی چه» که مستندات، نمونه‌کدها و سرور MCP نشان
می‌دهند. یکی‌شان بدون دیگری کافی نیست، و نگه داشتن متن فارسی داخل `description`
یک enum عملاً غیرقابل مصرف است.

پس عددهای V3 در spec می‌مانند، متن‌ها در `specs/v3/codes/`، و
برنامه [`scripts/validate.py`](scripts/validate.py) شکست می‌خورد اگر این دو از هم
واگرا شوند.

## پوشش جدول‌های کد V3

<div dir="rtl">

| جدول                                                | محتوا                                                    |
| --------------------------------------------------- | -------------------------------------------------------- |
| جدول [خطاها](specs/v3/codes/error-codes.yaml)       | ۲۰ کد خطا، هر کدام با علت، راهکار و دسته `retry`         |
| جدول [تحویل](specs/v3/codes/status-codes.yaml)      | ۲۲ وضعیت پیامک، از `0` تا `21`، هر کدام با `disposition` |
| جدول [قالب‌ها](specs/v3/codes/template-status.yaml) | ۳ وضعیت تأیید قالب                                       |

</div>

دسته `retry` می‌گوید تکرار درخواست فایده دارد یا نه، و `disposition` می‌گوید
حلقه استعلام وضعیت کِی باید بایستد. هر دو برای این‌اند که برنامه بدون حدس زدن
تصمیم بگیرد.

## دو نکته که در کد لازم می‌شود

<div dir="rtl">

| نکته                                  | جزئیات                                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| نام فیلد فرستنده در `GetInbox` نسخه ۳ | `Form` است، نه `From`. عیناً همین‌طور مستند شده تا کد شما با پاسخ واقعی بخواند                        |
| وضعیت قالب نسخه ۳                     | پنل کاربری چهار حالت نشان می‌دهد و بین دو نوع رد شدن فرق می‌گذارد، ولی API برای هر دو `3` برمی‌گرداند |

</div>

## عملیات افزوده‌شده نسخه ۳

متد `SendTokenSingleConcatParam` دو عملیات `GET` و `POST` دارد.
مقدارهای قالب در رشته `p` با جداکننده `;` فرستاده می‌شوند.
روش `POST` کلید و مقدارها را در بدنه JSON می‌گیرد.
عملیات افزوده‌شده از Swagger نسخه ۳ استخراج شده‌اند و متدهای موجود تغییر نکرده‌اند.

## اعتبارسنجی

بررسی ساختار، جدول‌های کد و قالب README به PyYAML نیاز دارد.

```bash
python3 scripts/validate.py
```

بررسی مستقل OpenAPI با تصویر Redocly انجام می‌شود:

```bash
docker run --rm -v "$PWD":/spec -w /spec redocly/cli lint specs/v3/openapi.yaml specs/v4/openapi.yaml
```

امکان استفاده از Podman به‌جای Docker وجود دارد. برای تصویر از پیش دریافت‌شده،
گزینه‌های `--pull=never --network=none` اجرای اعتبارسنجی بدون شبکه را فراهم می‌کنند.
قواعد و استثناهای اعتبارسنجی در [پیکربندی Redocly](redocly.yaml) ثبت شده‌اند.
